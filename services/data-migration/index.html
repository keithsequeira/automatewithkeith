Everyday examples

When the history
doesn’t come along.

The useful move is rarely “export everything.” It is getting a set of records your team can work from, with a way to check that the important parts survived.

01 / OLD FILES

The history is in a workbook nobody wants to replace.

Customers, jobs, or invoices have been copied forward for years. The file works, barely, and a new system feels risky because that file is the memory of the business.

A clear picture of what is in there before anything moves.
02 / TWO SYSTEMS

The new tool is live, and the old one is still open.

People keep checking the old system because a balance, a note, or a past job did not come across. The team is doing the work twice until they trust the new records.

A sample you can compare before the old system is retired.
03 / MESSY RECORDS

A straight copy would move the mess, too.

The same customer appears three times. A column meant one thing in 2019 and something else last year. Loading it all unchanged would make the new system harder to use.

Duplicates and gaps flagged before they become the new normal.

The aim is records your team can rely on. You still decide what is kept, what is merged, and what is left behind.

How we start

What people
actually open.

You don’t need an export ready. We start with the lists, histories, and notes someone uses in a normal week.

I work with you directly. We agree what “correct” looks like before any record is treated as finished.

01

Find the records in use.

We look at the files and screens people open, not every archive that happens to exist.

02

Agree how to check them.

We decide which details matter, what to do with duplicates, and how you’ll review a sample.

03

Move them in stages.

The old records stay available until the new ones have been checked against real work.
